# HydroHack — Ship Hydrostatics & Stability Solver

From-scratch computational tool for the **WAVEZ 2026 HydroHackathon**
(IIT Madras, Department of Ocean Engineering, 25–26 April 2026).

The solver reads an Excel offsets table and main particulars, then
computes upright hydrostatics and large-angle stability curves using
Simpson's-rule integration and 2-D polygon clipping. It satisfies the
competition rule that no commercial naval-architecture or pre-built
hydrostatics library may be used — only NumPy, pandas, openpyxl, and
matplotlib are imported.

|---|---|---|
| Hydrostatics | Displaced volume | ∇ |
| | Mass / weight | Δ, W |
| | Waterplane area | Aw |
| | Long. centre of buoyancy | LCB |
| | Long. centre of flotation | LCF |
| | Vert. centre of buoyancy | KB |
| | Transverse waterplane MoI | IT |

## Quick start

```bash
# 1) Create a virtual environment and install dependencies
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 2) Run the synthetic-hull validation (writes a sample workbook too)
python tests/synthetic_box.py

# 3) Run the solver on a real input workbook
python -m hydrohack.cli --input data/your_ship.xlsx --output outputs/

# Optional: change heel-angle grid (start:stop:step in degrees)
python -m hydrohack.cli -i data/your_ship.xlsx -o outputs/ --angles 0:90:2
```

## Input file format

The reader is **schema-tolerant** but expects *some* version of the
following layout. See `data/sample_box.xlsx` (auto-generated by
`tests/synthetic_box.py`) for a concrete example.

### Particulars sheet

A two-column key/value layout. Aliases are accepted (case-insensitive,
whitespace-insensitive — e.g. "Length Between Perpendiculars" works
just like "LBP"). Required keys:

| Canonical | Aliases | Unit |
|---|---|---|
| `LBP` | length, length between perpendiculars | m |
| `B` | beam, breadth | m |
| `D` | depth, molded depth | m |
| `T` | draft, draught, design draft | m |
| `rho` | density, water density, fluid density, ρ | t/m³ (or kg/m³) |
| `KG` | VCG, vertical centre of gravity | m |
| `Station spacing` | δx, dx | m (optional if LBP given) |
| `Waterline spacing` | δz, dz | m (optional if D given) |

### Offsets sheet

A 2-D block of half-breadths in metres. Either orientation works —
the loader picks the larger axis as stations. Optional axis-label row
(z values) and column (x values) are auto-detected and stripped.

```
x \ z   0.0   1.0   2.0   3.0   4.0   ...   D
0.0     0.0   y₀₁   y₀₂   ...
Δx      0.0   y₁₁   ...
2Δx     ...
...
LBP     ...
```

## Numerical methodology

* **Upright hydrostatics** — sectional areas A(x_i, T) are obtained by
  Simpson's rule over the waterlines (with a partial-trapezoid closure
  to the exact draft), then volume / longitudinal-moment / vertical-
  moment integrals are taken by Simpson's rule along the stations. The
  waterplane integrals (Aw, LCF, IT, IL) reduce to 1-D Simpson sums of
  `b(x)`, `x·b(x)`, `b(x)³` and `x²·b(x)`.

* **Heeled stability (GZ / KN)** — at each heel angle φ, every station
  cross-section polygon is rotated by `R_x(−φ)` into the world frame
  (gravity along −z, free surface horizontal). The waterline height is
  bisected so the Simpson-integrated displaced volume matches the
  upright `∇`. Polygon clipping (Sutherland-Hodgman, single half-plane)
  yields the wetted area and centroid; the KN arm is the y-coordinate
  of B′ in world frame, and `GZ = KN − KG·sinφ`. Trim is held at zero
  (LCG = LCB).

* **Even-sample fallback** — Simpson's 1/3 needs an even number of
  intervals. When a user provides an even sample count we apply
  Simpson on the first n−1 samples and a trapezoid on the final
  sub-interval, which preserves O(h²) accuracy.

## Validation

`tests/synthetic_box.py` tests every quantity against the closed-form
result for a wall-sided rectangular block (L=100 m, B=12 m, D=8 m,
T=4 m, ρ=1.025 t/m³, KG=3 m). The upright pass agrees to **machine
precision**; the GZ curve at moderate heel matches the wall-sided
analytical formula `GZ = (GM + ½·BM·tan²φ)·sinφ` to ~10⁻⁹ m. At 90°
heel the solver returns GZ = 1.000 m exactly (analytical answer).

## Outputs

Running the CLI writes to `--output`:

* `hydrostatics.csv` — single-row table of upright results (∇, Aw,
  LCB, LCF, KB, BMt/l, KMt/l, GMt/l, weight)
* `gz_curve.csv` — heel angle, KN, GZ, equilibrium waterline, B′_y, B′_z
* `gz_curve.png`, `kn_curve.png`, `body_plan.png`

## Assumptions / limitations

* Trim is held at zero throughout the GZ sweep (longitudinal balance
  is not iterated). For deeply-inclined hull forms this can shift max
  GZ by a few percent.
* The hull is closed at the deck (no down-flooding openings).
* Linear interpolation of half-breadths between waterlines (cubic
  splines could be added but are not required by the rulebook).
* ρ is assumed in t/m³ if the value is < 10, otherwise kg/m³.
